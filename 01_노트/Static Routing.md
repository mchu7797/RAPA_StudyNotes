# 개념
관리자가 직접 목적지 네트워크와 Next-Hop(또는 출구 인터페이스)을 지정하여 라우팅 테이블을 구성하는 방식이다. 네트워크 변화가 있어도 자동으로 갱신되지 않으며, 관리자가 직접 수정해야 한다.

## 특징

| 항목 | 내용 |
|------|------|
| **AD 값** | 1 (직접 연결 다음으로 신뢰도 높음) |
| **자동 갱신** | 불가 (관리자가 수동 변경) |
| **리소스 사용** | 매우 낮음 (라우팅 프로토콜 없음) |
| **적합한 환경** | 소규모, 단순한 네트워크 / 특정 경로 강제 지정 |

## IOS 설정
```bash
! 기본 정적 경로
ip route [목적지 네트워크] [서브넷 마스크] [Next-Hop IP | 출구 인터페이스]

! 예시: 192.168.2.0/24로 가는 경로를 10.0.0.2를 통해
ip route 192.168.2.0 255.255.255.0 10.0.0.2

! Default Route (모든 목적지)
ip route 0.0.0.0 0.0.0.0 10.0.0.1
```

## Dynamic Routing과 비교

| | Static Routing | Dynamic Routing |
|-|---------------|----------------|
| 설정 | 수동 | 자동 (프로토콜) |
| 장애 대응 | 수동 수정 필요 | 자동 재계산 |
| 리소스 | 적음 | 많음 |
| 확장성 | 낮음 | 높음 |

# 핵심 포인트
- 네트워크 구조가 변해도 라우팅 테이블이 **자동으로 바뀌지 않음** → 관리자 개입 필수
- Default Route(`0.0.0.0/0`)는 일치하는 경로가 없을 때 사용하는 최후 경로
- 소규모 환경 또는 특정 경로를 **고정**해야 할 때 유용
